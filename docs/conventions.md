# Conventions — match-padel-api

## Naming

| Thing | Convention | Example |
|---|---|---|
| Files | kebab-case | `match.service.ts` |
| Classes | PascalCase | `MatchService` |
| Functions / methods | camelCase | `findActiveMatches()` |
| Variables | camelCase | `activeMatch` |
| Global constants | UPPER_SNAKE | `MAX_PLAYERS_PER_MATCH` |
| DB tables (reference) | snake_case | `court_reservations` |
| HTTP routes | kebab-case | `/club-staff/:clubId` |
| Error codes | UPPER_SNAKE | `MATCH_NOT_FOUND` |

## Domain structure — required files

Each domain MUST have exactly these 5 files (plus the `__tests__/` folder):

```
domains/matches/
├── matches.routes.ts
├── matches.controller.ts
├── matches.service.ts
├── matches.repository.ts
├── matches.validators.ts
└── __tests__/
    └── matches.test.ts
```

Do not create extra files unless they are specific workers (`matches.elo-worker.ts`).

## Types

- Supabase table types come from `src/types/supabase.ts` (autogenerated with `supabase gen types typescript`)
- Request/response types are defined in `matches.validators.ts` as Zod inference: `type CreateMatchInput = z.infer<typeof createMatchSchema>`
- **Never** hand-write `interface Match { id: string; ... }` if the type exists in supabase.ts

## Validators (Zod)

Define schemas in `<domain>.validators.ts` and export them. The controller imports and uses them:

```typescript
// matches.validators.ts
export const createMatchSchema = z.object({
  clubId: z.string().uuid(),
  courtId: z.string().uuid(),
  startTime: z.string().datetime(),
  minCategory: z.enum(['1', '2', '3', '4', '5', '6', '7']),
})
export type CreateMatchInput = z.infer<typeof createMatchSchema>

// matches.controller.ts
const input = createMatchSchema.safeParse(req.body)
if (!input.success) {
  return res.status(400).json({
    success: false,
    error: { code: 'VALIDATION_ERROR', message: 'Invalid input', details: input.error.flatten() }
  })
}
```

## Errors

Always use the envelope format. Create an `AppError` class in `src/lib/errors.ts`:

```typescript
throw new AppError('MATCH_NOT_FOUND', 'The match does not exist', 404)
```

The global `errorHandler.ts` catches it and builds the response.

## Logging

```typescript
import { logger } from '@/lib/logger'

logger.info({ matchId, userId }, 'Score accepted')
logger.error({ err, matchId }, 'ELO calculation failed')
```

Always pass context as the first argument (object), message as the second.

## Imports

Use path aliases defined in `tsconfig.json`:
- `@/domains/...`
- `@/middleware/...`
- `@/lib/...`
- `@/types/...`

Do not use relative paths like `../../..`.

## HTTP Status codes

| Situation | Status |
|---|---|
| Success with data | 200 |
| Successful creation | 201 |
| Validation failed | 400 |
| Not authenticated | 401 |
| No permissions | 403 |
| Not found | 404 |
| Conflict (already exists) | 409 |
| Internal error | 500 |

## Environment variables

Always access via `process.env.NAME`. If it is required and missing, the process must fail on startup (validate in `src/lib/config.ts`).
